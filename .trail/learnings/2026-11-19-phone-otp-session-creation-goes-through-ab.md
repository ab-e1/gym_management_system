## Decided
- Sessions for the phone+OTP login flow are created via a direct Drizzle insert into the sessions table, inside the same transaction that burns the OTP (deletes the verifications row). Atomic OTP-burn + session-grant is the actual point of building a custom OTP engine instead of using Better Auth's phoneNumber plugin end-to-end.
- Tokens are high-entropy (32 random bytes / 256 bits) generated by the app, not produced by Better Auth's internal adapter. better-auth and @better-auth/drizzle-adapter should be pinned to an exact version (not a caret range), since direct session inserts couple to Better Auth's session-read path.
- Offline front-desk check-in is an append-only IndexedDB queue on the frontend, synced via the existing Bearer token on reconnect. No backend changes needed for this.
- Switching the active gym branch reuses the same session/Bearer token via a dedicated endpoint that updates sessions.activeGymId in place, rather than adopting Better Auth's multiSession plugin.

## Tried and ruled out
- Better Auth's internalAdapter.createSession() for session creation: rejected because it can't join the same Drizzle transaction as the OTP-burn delete, reopening the atomicity gap the custom OTP engine exists to close. Its main advantage (automatic Redis mirroring) isn't a current requirement, and auth.$context.internalAdapter is undocumented internal API, not a stable surface to depend on.
- Running Better Auth's built-in phoneNumber plugin alongside the custom OTP flow: both write into the same verifications table (one plaintext, one HMAC-hashed) and both sets of routes are live under the /api/v1/auth/* catch-all, so they collide on the same identifier. The plugin needs to be removed/disabled, not left running in parallel with the custom flow.

## Watch out
- As of this session, verifyOtp's failed-attempt counter did `set({ attempt: +1 })`, which resets the counter to 1 instead of incrementing it, breaking the "5 bad attempts burns the OTP" brute-force guardrail this plan depends on. The same update call was also missing its `await` inside the transaction callback, so the write could race the transaction commit. Both need fixing before the lockout behavior can be trusted.
- auth.ts still registers the stock phoneNumber plugin with a stub sendOTP that only console.logs. package.json still pins better-auth and @better-auth/drizzle-adapter with a caret range, not an exact version.
